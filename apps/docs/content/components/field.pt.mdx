## Visão geral

`Field` é a família de layout de formulário. Um `Field` empilha um `FieldLabel`, um controle (`Input`, `Textarea`, `Select`, `Checkbox`, `RadioGroupItem`, `Switch`), um `FieldDescription` e um `FieldError`, com o espaçamento e a ligação do label já resolvidos. `FieldSet` e `FieldGroup` agrupam campos, e um `Field` dentro de um `FieldLabel` vira um **card de escolha**: o card inteiro é a área de clique do radio ou checkbox que está dentro dele.

Use `Field` para o layout de qualquer formulário. Quando o estado do formulário vive no react-hook-form e você quer `id`, `aria-describedby` e `aria-invalid` ligados a partir dele, use o [Form](/components/form); os dois se combinam. Para uma legenda solta, o `Label` basta.

É um port da família `Field` do shadcn/ui, nas duas edições: as mesmas dez partes, as mesmas props, os mesmos nomes de `data-slot`.

## Anatomia

```text
FieldSet                      fieldset, coluna flex (gap-6)
├─ FieldLegend                legend (variant: legend | label)
├─ FieldDescription           texto de apoio em tom suave
└─ FieldGroup                 empilha campos (gap-7); raiz da container query
   ├─ Field                   role=group, orientation: vertical | horizontal | responsive
   │  ├─ FieldLabel           label; envolver um Field inteiro cria um card de escolha
   │  ├─ control              Input, Select, Textarea, Checkbox, RadioGroupItem, Switch
   │  ├─ FieldContent         coluna de label + descrição ao lado de um controle
   │  │  ├─ FieldTitle        texto com cara de label que não é um label
   │  │  └─ FieldDescription
   │  └─ FieldError           role=alert; oculto quando vazio
   └─ FieldSeparator          linha, com texto centralizado opcional
```

## API

Cada parte é um componente React e um elemento Angular. Os nomes são os mesmos, em kebab case com o prefixo `gr-` no lado Angular: `FieldLabel` é `gr-field-label`. Toda parte também aceita `className` (Angular: `class`), combinado com `cn`. No React toda parte repassa as props nativas do seu elemento.

### `<Field>` / `<gr-field>`

Um controle com seu label, texto e erro. Renderiza uma `div` com `role="group"` e `data-orientation`.

| Prop          | Tipo                                         | Padrão       | Descrição                                                                               |
| ------------- | -------------------------------------------- | ------------ | --------------------------------------------------------------------------------------- |
| `orientation` | `"vertical" \| "horizontal" \| "responsive"` | `"vertical"` | Layout das partes. `responsive` é vertical até o `FieldGroup` ter largura `md` (28rem). |

O estado vive em atributos, como no shadcn: `data-invalid="true"` deixa o texto destrutivo (ponha `aria-invalid` no controle também), e `data-disabled="true"` esmaece o label e o texto (ponha `disabled` no controle também).

### `<FieldLabel>` / `<gr-field-label>`

Um `<label>` nativo. Envolver um `Field` inteiro nele cria um card de escolha.

| Prop      | Tipo     | Padrão | Descrição                       |
| --------- | -------- | ------ | ------------------------------- |
| `htmlFor` | `string` | -      | Id do controle. Angular: `for`. |

### `<FieldTitle>` / `<gr-field-title>`

Texto com cara de label que não é um `<label>`: o título do conteúdo de um card de escolha, onde o label é o card inteiro.

### `<FieldDescription>` / `<gr-field-description>`

Texto de apoio em tom suave. Links dentro dele ficam sublinhados.

### `<FieldError>` / `<gr-field-error>`

A mensagem de validação, `role="alert"`. Oculta quando vazia.

| Prop     | Tipo                                       | Padrão | Descrição                                                                                             |
| -------- | ------------------------------------------ | ------ | ----------------------------------------------------------------------------------------------------- |
| `errors` | `Array<{ message?: string } \| undefined>` | -      | Mensagens. Uma vira texto, várias viram lista; duplicadas são removidas. Os children vencem `errors`. |

### `<FieldContent>` / `<gr-field-content>`

A coluna que guarda um label e uma descrição ao lado de um controle, em um `Field` horizontal.

### `<FieldGroup>` / `<gr-field-group>`

Empilha `Field`s (`gap-7`) e é a raiz da container query que `orientation="responsive"` lê. Grupos podem se aninhar.

### `<FieldSet>` / `<gr-field-set>`

Agrupamento semântico de campos relacionados. O React renderiza um `fieldset`; o Angular renderiza um `role="group"` nomeado pelo seu `FieldLegend`.

### `<FieldLegend>` / `<gr-field-legend>`

O título de um `FieldSet`.

| Prop      | Tipo                  | Padrão     | Descrição                                    |
| --------- | --------------------- | ---------- | -------------------------------------------- |
| `variant` | `"legend" \| "label"` | `"legend"` | `legend` é `text-base`; `label` é `text-sm`. |

### `<FieldSeparator>` / `<gr-field-separator>`

Uma linha entre campos. Passe children (React) ou projete conteúdo (Angular) para ter texto centralizado sobre a linha.

## Variações

### Card de escolha

Envolva um `Field` em um `FieldLabel` e ponha um `RadioGroupItem` dentro: o card inteiro seleciona o radio, e o card selecionado fica em destaque.

<ComponentPreview name="forms/field-choice-card">
  <FieldChoiceCardPreview />
</ComponentPreview>

```tsx
<RadioGroup defaultValue="kubernetes">
  <FieldLabel htmlFor="kubernetes">
    <Field orientation="horizontal">
      <FieldContent>
        <FieldTitle>Kubernetes</FieldTitle>
        <FieldDescription>Run GPU workloads on a K8s cluster.</FieldDescription>
      </FieldContent>
      <RadioGroupItem value="kubernetes" id="kubernetes" />
    </Field>
  </FieldLabel>
</RadioGroup>
```

O card selecionado recebe a borda `--primary` e o preenchimento `--accent`, ambos tokens semânticos, então cada tema e os dois modos mantêm o seu próprio visual de selecionado, sem opacidade literal. No tema neutro o preenchimento é o cinza discreto de `--accent` e a borda o `--primary` forte; um tema colorido tinge o card com o seu próprio accent.

| Token       | Usado em                          |
| ----------- | --------------------------------- |
| `--primary` | borda do card selecionado         |
| `--accent`  | preenchimento do card selecionado |
| `--border`  | borda do card não selecionado     |

## Acessibilidade

- **Ligação do label**: `FieldLabel` é um `<label>` nativo; `htmlFor` (Angular: `for`) deve casar com o `id` do controle. Clicar no label, ou no card inteiro, ativa o controle.
- **Agrupamento**: o React renderiza um `<fieldset>` nativo com um `<legend>`. O Angular renderiza `role="group"` e aponta `aria-labelledby` para o `FieldLegend`. Cada `Field` também é um `role="group"`.
- **Erros**: `FieldError` é `role="alert"`, então uma mensagem que aparece é anunciada. Combine com `aria-invalid` no controle.
- **Cards de escolha**: o radio ou checkbox de dentro continua sendo o controle focável e operável por teclado; o card só amplia a área de clique. Grupos de radio mantêm o roving tabindex e as setas.
- **Contraste**: o card selecionado é `--primary` sobre `--accent`, e `FieldDescription` é `--muted-foreground`, os mesmos pares que o resto do sistema já usa.
